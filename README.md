# CS-230
CS 230 Portfolio Reflection: The Gaming Room
Client and Software Requirements
The client for this project was The Gaming Room. They wanted to develop a game called Draw It or Lose It that could support multiple players and teams. The software needed to work across different operating systems and allow multiple players to participate in the same game. It also needed to keep track of game information and make sure each game and team had unique names and identifiers.
What I Did Well
I think I did a good job organizing the software design document and explaining the requirements clearly. I compared different operating systems and considered factors such as security, performance, cost, and compatibility. This helped me recommend an approach that would meet the client's needs.
What I Found Helpful About the Design Process
Working through the design document helped me understand the importance of planning before writing code. It gave me a better idea of how the different parts of an application would work together. Having a clear plan also makes it easier to identify possible problems early and avoid unnecessary changes during development.
What I Would Revise
If I could revise one part of my work, I would improve the section comparing operating platforms. I would include more details about the advantages and disadvantages of each option and explain my recommendations more clearly. This would make it easier for the client and development team to understand why a particular platform would be the best choice.
Understanding the User's Needs
I focused on the client's need for a game that could support multiple players, organize teams, and work across different platforms. I used these requirements to guide my software design decisions. Understanding the user's needs is important because the software must solve the client's problem and provide a good experience for the people using it. Without clear requirements, developers could spend time building features that do not meet the client's expectations.
My Approach to Software Design
My approach to software design was to review the requirements, identify the main challenges, and compare possible solutions before making recommendations. I also considered security, scalability, performance, and cost. In future projects, I would continue using this approach and include diagrams, research, and feedback throughout the design process. I believe planning carefully and reviewing requirements early can help create software that is reliable, useful, and easier to maintain.
Conclusion
This project helped me understand how important software design and documentation are in software development. I learned that a good design should consider both technical requirements and the needs of the client. I can use these skills in future projects to plan applications more effectively and communicate my ideas clearly to clients and development teams.
